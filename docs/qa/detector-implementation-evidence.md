### Root-derived structural identity logic (2026-11-07)

The detector now has an estimated-only structural strategy that combines `AccessibilityNodeInfo.hashCode()` with a bounded topology of up to 16 immediate children. The signature uses only the node handle, static resource-name fragments, class names, child counts, and visibility flags. It is hashed immediately with the app/profile's rotating local salt and rederived from the current root both when a candidate is observed and at its one-second deadline. A complete scan must find exactly one visible configured node. Missing, ambiguous, incomplete, or changed root identity cancels the candidate. Stable opaque tokens retain the existing current-root verification and are still required for confirmed counts.

A structural signature change alone does not count as an item transition. The first candidate may seed from a recognized feed entry; later structural candidates also require an observed pager transition. This avoids counting layout churn by itself. Pager transition remains transition evidence only and is not the identity. The exact app/version signature still must establish same-item stability, changed-item distinction, revisit behavior, and the SRS accuracy gate before a profile can be enabled.

A focused review rejected an earlier draft that compared only the cached active fingerprint/index at the deadline; that draft was removed before final verification because it did not prove current-item identity. The final guard requires the freshly derived root hash to match the candidate. `DetectorProfiles` remains empty, so this logic does not enable counts for Instagram or YouTube. Their sampled structural signal was unchanged for Instagram and inconclusive for YouTube.

## Rulings after whole-change review

- **Ruling: disable the historical Instagram profile** — the pager marker alone cannot identify the current item at the deadline or seed a stationary first item. Continuing to count would imply a one-second item exposure without the required evidence. Cost: no new Instagram estimates until a supervised fixture establishes independent signals.
- **Ruling: keep duplicate hashes in process memory** — SharedPreferences cannot guarantee physical deletion at five minutes while the app is idle. Existing `recent_item|` keys are removed when the app opens its store. Cost: a service/process restart can lose five-minute revisit deduplication; confirmed profiles cannot ship until a durable, bounded retention mechanism is implemented and tested.
- **Ruling: receive window state events across packages when a validated profile or explicitly enabled debug probe is active** — the service needs foreign window exits to cancel dwell; the probe needs to discover selected app events. It reads only the package name on foreign events and returns before accessing source nodes or root content. Cost: broader metadata delivery must be checked against Android/Play policy and device behavior before release.
