# Rooko project context

## Focus tools status (2026-11-25)

- The user selected eight focus concepts for [PRD section 4.4](docs/PRD.md#44-creator-shelf-and-candidate-focus-tools): Creator shelf, Hashtag shelf, Purposeful launch, YouTube long-video mode, Reels/Shorts entry guard, Sleep routine, Whole-app limit, and Focus presets. Creator shelf and Hashtag shelf are approved active features: they store normalized Instagram destinations locally and open profiles or tag searches without requiring tracking consent or Accessibility access. The other six concepts remain exploratory. Feed time and count allowances were removed; the only candidate usage limit covers the whole app.
- Hashtag Shelf stores normalized Unicode tags in a separate local preference list, opens Instagram tag search with a package-targeted HTTPS intent, and offers manual-search, browser, and copy fallbacks. It does not filter Reels; saved tags stay out of analytics and tracking records. The feature is free and adds no permission or network request.
- Play review assessment (2026-11-25): [Google's Accessibility policy](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en) permits non-disability uses with an accurate declaration, separate in-app disclosure, and affirmative consent; deterministic user-defined rules are allowed, while autonomous decision-making is prohibited. [Device and Network Abuse](https://support.google.com/googleplay/android-developer/answer/16559646?hl=en) prohibits unauthorized interference with other apps, including ad-display interference. Updated disclosure and declaration are necessary if Accessibility use expands to feed guards or pauses, but wording alone cannot establish approval. Keep the remaining candidate focus features exploratory until an implemented build is reviewed.

## Instagram estimated counter diagnosis (2026-11-23)

- On OPPO CPH2565 / Android 15, Instagram `456.1.0.56.78` undercounted user-confirmed ten-Reel sessions after the first coalesced-scan change. A content-free debug summary showed hundreds of recognized feed/item observations but only 16 item hashes and five counted outcomes. The service had cancelled its 150 ms candidate confirmation on each new event and scanned the full root on every routine event. The current build preserves scheduled confirmation and rate-limits routine estimated scans to 250 ms; scroll and window transitions remain immediate. Android tests and build/install passed. In one subsequent user-ground-truthed run entered from Instagram Home, 10 confirmed Reel changes produced 11 counts (first visible Reel plus 10 changes), matching the product count definition; a brief stationary check added none. See `docs/qa/2026-11-23-instagram-scan-backlog.md`. Do not claim broad Instagram accuracy or validated coverage from this one device.

## Architecture and foundation

- Flutter/Dart owns shared UI; Kotlin owns Android-only monitoring, permission/service lifecycle, persistence, and the typed platform bridge.
- Android namespace and application ID: `com.heykakaa.rooko`; minimum SDK: 29.
- Dart design tokens in `lib/core/design_system/` are canonical. `web/global.css` mirrors them.
- Google Sans is the global UI typeface in Flutter and web previews. Local regular, medium, semibold, and bold assets are bundled with the OFL and trademark notice; system sans is the fallback.
- The shared UI palette is black and white dominant: Light canvas/cards `#FFFFFF`; Dark canvas `#080808` and cards `#171717`; AMOLED canvas/cards `#000000`. General text colors stay black/white. Dark and AMOLED selected controls use near-black `#303030` fills with white labels and icons for contrast; neutral gray also serves supporting text, outlines, dividers, and disabled states. This supersedes the too-light `#777777` control fill. Only Rook and supported-app logos retain color. Dart `AppColors` and `AppTheme` are canonical; `web/global.css` mirrors them.
- HugeIcons glyphs are accessed through `AppIcons` and rendered through `AppIcon`.
- Windows build workaround: `android/gradle.properties` disables Kotlin incremental compilation because `flutter run` hit duplicate Kotlin cache registrations in plugin compile tasks. Use Android Studio's bundled JBR and the workspace SQLite temp directory for Room verification.
- Project guidance and routing live in `AGENTS.md`; local agent skills live in `.agents/skills/`.
